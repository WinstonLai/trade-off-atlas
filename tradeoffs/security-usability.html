Security vs. usability

Each security control adds protection and friction. A few well-chosen ones raise security a lot. Pile on too many and people work around them, so real security falls even as the rules get stricter.

Protectionvs.Ease of use

The trade-off

Longer passwords, frequent changes, extra login prompts, short session timeouts and locked-down file sharing all make a system harder to break into, on paper. They also cost time and patience. Up to a point, people accept the cost and protection rises. Past it, they find ways around: passwords written on sticky notes, shared accounts, files emailed to personal addresses, the same password with a number at the end.

Anne Adams and Angela Sasse's 1999 paper "Users are not the enemy" documented this: rules that ignore how people work get bypassed, and the workarounds are often worse than no rule. In 2017 the US standards body NIST revised its password guidance (SP 800-63B) to drop mandatory periodic changes and complex composition rules for the same reason. So real security is protection on paper multiplied by how many people actually follow it. The best way to improve both is better design: passkeys, single sign-on, password managers, and prompts that appear only when a login looks risky.

How to use it

  1. Measure workarounds. Shared accounts, password resets and shadow IT show where friction is too high.
  2. Spend friction where the risk is. Ask for extra verification on payments and admin actions, not on every page view.
  3. Replace rules with better tools. A password manager or passkey is both safer and easier than a complex password rule.
  4. Make the secure path the easy path. If the approved file-sharing tool is slower than email, people will use email.

Example

A company required password changes every 30 days and a 15-minute session timeout. The help desk handled hundreds of reset requests a month, and an audit found that most new passwords were the old one with a changed digit. It switched to single sign-on with passkeys, longer sessions on managed devices, and an extra check only for unusual logins. Reset requests fell sharply, and phishing tests showed fewer accounts compromised.

Watch out for

  • The curves here are illustrative. The workaround threshold depends on the people, the task and the culture.
  • Usability isn't permission to skip controls. Some friction is necessary. The goal is the most real protection, not the least friction.
  • Attackers aren't affected by friction. Controls that only slow down honest users, like security questions with guessable answers, add cost without much protection.
